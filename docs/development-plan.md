# 文言 AI 学习智能体：合并执行计划

更新：2026-10-07。依据《文言文 AI 学习智能体 V1.0 工程规格》、录音整理和新增“原文全文点读，词—句—段—篇—时代五层语境”及“逐字词本句义、变量分类与其他语境知识库”要求。

## 产品与架构边界

真实全栈项目：React / TypeScript → FastAPI → SQLAlchemy / SQLite。训练状态由后端领域层决定，前端只提交学习意图并渲染快照。教研资料是数据，不是可执行指令。保留黑白阅读界面和手机端支持。

学习闭环保持“暂放 → 获取新语境 → 回溯 → 证据与判断 → 陌生文迁移”。展示原文不等于展示完整翻译；扩大语境不自动选择答案、认定证据、发积分或跳过迁移。

## 已完成基础：语境阅读接入训练闭环

| 工作 | 实现与验收 |
| --- | --- |
| 后端领域命令 | REQUEST_MORE_CONTEXT 校验冻结原文定位，生成五层语境选择；不改变解题进度。REVISIT_VARIABLE 要求此前暂放并清除暂放标记。 |
| 前端原文点读 | 字词点击、词组起止选择、五层标尺切换；请求成功后以服务端定位为准。失败不把未保存选择显示为已保存。 |

| 正文排版 | 阅读栏使用容器宽度决定双栏或上下排列，避免侧栏挤压正文；重复目标词不截断题干；字词及标尺支持键盘。 |

### 接口与数据约定

沿用 `POST /api/v1/training/sessions/{session_id}/commands`，必须携带 `Idempotency-Key` 和 `expected_state_version`。

```json
{
  "type": "REQUEST_MORE_CONTEXT",
  "expected_state_version": 1,
  "payload": {
    "paragraph_index": 0,
    "start": 1,
    "end": 2,
    "scope": "SENTENCE"
  }
}
```

位置使用 **Unicode 码点**，段号从 0 开始，`[start,end)`；不能使用 JavaScript UTF-16 下标直接传给后端。前端统一以 `Array.from` 计算。最多选择同段 80 个码点，拒绝空白/纯标点及越界请求。句界按 `。！？`，分号保持句内语境。

`context_selection` 保存 `paragraph_index/start/end/token/sentence/paragraph/scope`。scope 为 WORD / SENTENCE / PARAGRAPH / WORK / ERA。事件 `training.context_expanded` 只记录位置、token、scope、stage，不复制整篇原文。

`reading_context` 保存段落、作者、时代、篇章说明、材料范围、资料版本、可选原文链接和教研词组。CORE 与 TRANSFER 在创建会话时同时冻结。编辑新版本不覆盖已开始的训练；只有新建会话使用新的语境资料。

### 材料范围与校勘

《岳阳楼记》原文参考 [维基文库](https://zh.wikisource.org/zh-hans/岳陽樓記)，简体和教学标点采用当前题干一致的“淫 / 曜 / 乎”异文，版本字段明示。本轮补齐其余 12 个来源单元，逐项范围、异文和原典链接见 [资料来源清单](material-sources.md)。宋史及劝学展示连续节选，不能称整篇全文；四个经典章节只对所选完整章负责。

## 当前迭代：Source / Review / Version 内容质量

- **来源资料**：8 个种子课程、16 个 CORE / TRANSFER 阶段关联 13 个来源单元；7 个 FULL、4 个 CHAPTER、2 个 EXCERPT，均登记作者、时代、材料范围、文本版本及原文链接。来源核对不是教师审核，不伪造审核人。
- **三处种子修订**：坐盗改为《晏子春秋·内篇杂下》并辨析犯罪义；送东阳迁移题改为连续原文，移除跨段拼接；“天下归仁”按朱熹《论语集注》“归犹与也”选用赞许、认可义，并明示解释版本，不将其宣称为所有注家的唯一解释。参见 [朱熹原文](https://m.gushiwen.cn/guwen/bookv_49f4c51c6425.aspx)。
- **保护已有内容**：只修正完整匹配旧种子 payload 和元数据的已发布课程；人工修改过的课程、草稿及历史学习快照不覆盖。修复可重复执行，不把新资料追写到旧会话。
- **审核发布**：保存草稿 → 人工核对 → 署名审核 → 发布。审核记录存 LessonReview，SHA-256 覆盖教材定位、教学元数据和两阶段解析后的原文资料，界面显示 12 位版本摘要。审核不自动发布；已发布课程实质修改后退回草稿并显示审核失效，无变化保存不使审核失效。
- **发布检查**：两阶段结构有效；作者、时代、已校订文本版本及公开 HTTP(S) 原文链接齐全；目标词和题文须匹配所引资料，题文必须是连续原文，忽略现代标点/空白差异。结构检查不代替教师核对题义、证据与异文。
- **版本冻结**：新会话一次解析资料并冻结两阶段正文，lesson 中保存 content_version / review_status / reviewer / reviewed_at；没有有效审核时署名及时间为空。旧会话照原快照继续训练，不静默修改答案或迁移文。
- **本地边界**：审核人为本地自填署名，尚未接入认证身份及权限。旧演示种子保持可测试的已发布状态，但明确标为未审核；新发布必须通过当前版本审核。不能将演示种子的旧发布状态宣传为正式教研认证。

### 新增接口

`POST /api/v1/admin/lessons/{lesson_id}/review`：`{ "expected_content_version": "页面详情所见的12位版本", "reviewer": "实际审核人", "note": "核对说明" }`，记录所读版本署名。`publish` 也必须携带 `expected_content_version`，直接取详情 GET 返回的 `review.content_version`，不能使用示例占位值。来源不就绪返回 422 `LESSON_REVIEW_NOT_READY`，发布无有效审核返回 409 `LESSON_REVIEW_REQUIRED`。读取管理资料包含 review 状态、摘要版本、审核时间与 issues。

审核、发布版本不一致分别返回 409 `LESSON_REVIEW_VERSION_CONFLICT` / `LESSON_PUBLISH_VERSION_CONFLICT`；PATCH 可选版本（兼容旧调用），前端始终提交并遇到冲突返回 `LESSON_EDIT_VERSION_CONFLICT`，不覆盖其他页面内容。列表刷新不替换正在编辑的详情版本，需重新读取原稿再核对；详情失败关闭表单，避免误写另一课程。

## 新增 P0：逐字词语境知识库（2026-10-07）

用户确认“变量／无变量”指需要随当前语境推断／在本句相对确定，不能解释为学生已知或未知。按 [知识库架构与内容约束](knowledge-base.md) 实施：版本化 ReadingDocument、逐字符 POSITION 与逐词 ANNOTATION 真实数据库、冻结会话位置 lookup、正文覆盖审计；阅读侧栏显示本句义、词性、分类证据以及其他已收录语境，继续保留词／句／段／篇／时代。

字词注释只作为阅读资料，不自动代答、认定证据或加分。所有新增条目为待教研审核草稿；词组包含字位覆盖不等于专名中的每个字有独立字典义。例证仅限当前材料，不宣称穷尽全部历史用法。初批难词之外，按逐句分词补齐现有 13 单元，完整性验收以 `knowledge_audit --require-complete` 和运行库 coverage 为准。

本轮由主分支实现点读面板、变量口径、进度展示、数据库级例证分页与集成验收；三个协作分支分别负责数据库接口及长篇内容、古文长篇资料、经典短篇及全文补注。文件分开，统一入库和回归。已保存学习记录、人工课程修改和原文版本不覆盖；不把词义草稿当作真人教师审定教材。

已验收 13 单元 4,362 / 4,362 正文字位的 3,495 条草稿，知识库声明与真实运行库一致；全量 97 项测试和前端构建通过，详情见 [知识库验收](knowledge-acceptance.md)。

## 后续次序：遵循总指南，不以页面数量代替完成度

1. **P0 内容质量与知识库**：先把现有原文逐字词的语境释义和分类落到库并验收全覆盖；继续做字词审核、同义项归并与真实例证扩充。题库原文版本与审核发布门槛已有实现，仍需真实教师核对题义、异文、读音、注释与评分规则，扩题时遵循相同流程。
2. **P0 推理表达**：从当前选证据、选词义扩展到稳定 span 标注、ReasoningGraph 最小结构、可复核的解释；补充开放判断验收用例。
3. **P0 AI 能力**：实现总指南的模型 Provider 接口、结构化输出、提示防泄漏与评测集，再接入真实模型。当前规则式判题 Demo 不等同于已经完成 AI 智能体。
4. **P0 运行安全**：账号鉴权、教研接口权限、数据备份/迁移、生产持久数据库、部署与跨设备恢复。当前本地内容管理无鉴权，不应暴露公网。
5. **P1 体验深化**：已有日任务、专题练习、错题与复习、报告及成就继续以真实学习数据验证；补多题型、难度分层和题库。随机选项已有实现，须持续回归正确率与会话内排序稳定性。
