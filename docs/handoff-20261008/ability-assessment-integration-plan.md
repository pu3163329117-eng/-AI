# 文言文平台能力分级与评测融合实施方案

日期：2026-10-07。状态：A / B 的技术基础和 C 的能力档案、持久学习队列已实现；真实教研审核与正式测评尚未开放。实际范围见 [首轮验收](assessment-pilot-acceptance.md) 和 [能力档案与队列验收](learning-path-acceptance.md)。

目标是在现有原文点读、五层语境、字词知识库和证据推理训练上，增加可解释的能力评测与学习推荐。采用用户提供的《文言文学习产品等级与评测模块优化计划书》中多维画像、断点恢复和表现回流的方向；调整材料分级、评分、可信度及数据保存方式。登录和权限按用户决定暂缓，本轮不进行公网发布。

实施顺序是内容依据、评测基础、学习推荐、表现回流、等级校准。每一阶段独立验收，不把资料覆盖、课程积分或训练完成次数当成能力测量。

## 当前基础与新增范围

| 模块 | 当前基础 | 融合后的新增能力 |
| --- | --- | --- |
| 学习入口 | 昵称和初中或高中阶段建档 | 不绑定年级的能力入口，提供正式测评和暂不测评两条路径 |
| 内容 | 版本化原文、FULL / CHAPTER / EXCERPT 范围、逐词位置注释和审核记录 | 课程能力等级、专项标签和经过核验的评测题 |
| 阅读 | 词、句、段、篇、时代五层点读 | 练习中保留；正式测评控制答案性注释的展示 |
| 训练 | 核心与迁移阶段、规则判断、定位证据、理由保存 | 明确记录首次作答、辅助使用及专项表现 |
| 报告 | 完成次数、积分、词义判断正确率和薄弱项 | 多维能力档案、样本数量、解释及版本历史 |
| 推荐 | 按阶段和课程顺序选择未完成课程、专题练习 | 按能力和短板生成有理由的学习队列 |

当前代码已提供四道轻自评和 24 题四维试测，候选池为 48 题；没有启用附件中描述的 12 道正式题或自动升降级。试测不产生正式 L1–L3 等级，也不改变档案或积分。当前知识库已完成位置覆盖与草稿入库，不等于已经通过真实教师核验。

本方案依赖的项目资料：[总开发指南](development-plan.md)、[知识库结构](knowledge-base.md)、[材料范围](material-sources.md)、[字词审核与推理验收](annotation-reasoning-acceptance.md)。

## 产品融合原则

### 能力等级与材料范围分离

保留三档面向学习者的能力名称：L1 基础级识字入境、L2 进阶级通篇理解、L3 高阶级深层理解。等级描述的是训练要求，不由文章长度或是否完整单独决定。

材料范围继续保存 FULL、CHAPTER、EXCERPT、PROMPT。完整短篇可以用于 L1；复杂节选可以用于 L3 的专项练习。标为通篇阅读的任务必须使用完整全文或完整章，并说明范围。现有《劝学》是连续节选，不能在未补齐原文前称为整篇全文；可以先用于字词、句式和语境标杆。

课程增加 `ability_level` 和 `dimension_tags`，不把现有字符串 `difficulty` 直接转成数值等级。教研逐项标定等级，未标定课程继续保留旧入口，但不参与正式能力推荐。`school_stage` 保留为教材背景与旧档案兼容字段，不再作为新能力推荐的唯一筛选条件。

### 能力证据与学习行为分离

能力画像采用 vocabulary、syntax、context、chapter、translation、transfer 六个维度。首次选择题测评只测前四项；翻译和迁移依据相应任务逐步积累。

没有合格观测时，分数为 `null`，界面显示待评估，并显示实际样本数量。不能用零分代替未测试，也不能用一次词义选择推导出篇章或翻译能力。主等级、专项能力和课程积分分别保存。

推断理由非空只表示已表达。当前证据覆盖规则不等于语义正确；未经教师或模型复核的理由不得用于开放推理评分。提示、查释义、重答和跳过记录为学习行为，不直接等同于能力差。

### 测评与学习模式分离

学习模式保留按需查释义、获取语境、提示和回溯。正式测评保留所需原文及非答案性背景，不展示正确答案、解析、目标词释义或会泄露答案的例证；相关限制必须在接口实现，不只隐藏按钮。

试卷冻结题干、原文版本、选项身份及排序，服务端保管正确答案和评分规则。刷新不能重抽试卷或重排选项；重复提交不能产生第二份结果。完成提交后才提供题目解析，后续复测使用新的试卷。

## 学习者页面流程

新用户建立档案后，选择开始能力测评，或先从基础练习进入。跳过测评时显示未测评和建议起点，不显示经过测量的 L1；保留以后补测的入口。已有用户无需重建档案，可以继续旧训练并自愿参加新测评。

页面流程为：学习目标自评 → 四维正式测评 → 能力结果 → 确认推荐起点 → 首页学习队列 → 原文训练 → 表现回流 → 学习报告。自评只影响目标和呈现说明，不替代客观得分。

| 页面 | 关键展示与交互 |
| --- | --- |
| 建档与起点 | 用途说明、开始测评、暂不测评；不新增头像设置前置门槛 |
| 测评进行页 | 当前维度、题号、预计剩余题数、上一题、下一题、跳过、服务端保存状态 |
| 测评恢复页 | 显示上次时间和已完成数量；继续或明确放弃后重新开始 |
| 结果页 | 推荐起点、四维分数与样本量、优势和补强项、评估充分度、推荐原因 |
| 首页 | 主线、补强、挑战任务；每项有来源范围、能力目标及推荐理由 |
| 训练页 | 保留现有证据链；说明当前是学习模式，不宣称为闭卷测评 |
| 学习报告 | 新增四维评测与真实专项记录；未测翻译和迁移显示待评估 |

用户手动选择更难或更易内容时，只改变练习方向，不覆盖测评结果。页面说明这是个人选择，不是能力重新定级。自评与客观结果不同，只解释测量范围和答题表现，不推断用户心理性格。

保持现有黑白风格。结果页以可读的横向能力条和样本说明为主，不用复杂图表替代解释。手机测评使用单栏、可达按钮和明确的保存状态；动画沿用减少动态效果设置，不延迟作答或保存。

## 内容标杆和题库建设

### 先核验原文与注释

先选现有《劝学》连续节选做字词标杆，逐句核验词项位置、本句义、词性、变量分类、推断依据及出处。专名和固定词组整体解释，不为拆开的每个字编造独立字典义；保留异文和不同解释的边界。

每条释义区分原典出处与注释依据。通过现有工作台保存草稿、记录修改、由实际审核人署名确认；没有实际审核人时维持待审核，不将程序检查当作人工审批。其他语境例句优先采用当前材料中的真实位置；新引入例句先登记来源与版本，不宣称穷尽全部用法。

如要开展整篇《劝学》训练，另建完整原文版本并补齐注释，不覆盖已经开始的节选会话。篇章测评另选已有完整材料，不能因标杆只覆盖一篇就用它代表全部文体能力。

### 建立独立的评测题库

评测题与课程题关联，但不直接复制现有学习页的题文和解析。每题至少保存：稳定题目 ID、版本、能力维度、L1–L3 难度、题型、题干、选项 ID、正确选项 ID、解释、知识点、原文版本与连续定位、审核状态及审核记录。

使用稳定选项 ID 判分，不使用随机排序后的 A 或数组下标作答案身份。新评测 API 在交卷前不返回正确选项、解析和内部评分字段。题目修改产生新版本；正在进行的试卷继续使用创建时的版本。

首轮试行目标是 24 道正式题：四维各 6 道，每维 L1、L2、L3 各 2 道，分层抽题。另设 4 道轻量自评，不计入客观能力分。8–10 分钟作为待试测的体验目标，不作为尚未验证的时长承诺。

最小试卷需要 24 道通过审核的题；建议建立至少 48 道的首批候选池，即四维三档每格 4 道。48 道不代表高质量或无限可重测，仍需来源多样性审核。题库不足时不凑数、不循环抽同一题，不宣称测完所有能力。

首轮保持固定分层试卷，不实施答对就升难度的自适应算法。不同维度尽量使用不同材料，同一原文关联题限制占比，避免熟悉一篇文章就被判断为通用高能力。

## 评分与结果解释

### 试行计分规则

第一版同维度题目等权；分别保留各难度层的正确率，先不启用附件中的 1.0、1.2、1.5 难度系数。正式引入难度加权时，必须按本次试卷最高可得分归一化，且不能把系数称为已校准的题目难度参数。

四维综合权重试行采用字词 30%、句式 25%、语境 25%、篇章 20%，统一写入评分配置。分维度同时返回 `presented_count`、`answered_count`、`skipped_count` 和 `correct_count`。试卷未完成时只显示进度，不生成最终等级；交卷时跳过题不取得分，并影响评估充分度。

存在整维未答、样本不足等情况时，综合结果可显示参考分，等级显示待确认或建议起点，不把已答维度重新加权后宣称完整测评。L2、L3 起点还需对应难度层的有效作答证据，不能只凭简单题总分判断。

附件中的 45 分和 75 分边界暂存为试行阈值，不自动对全部历史用户定级。上线前用代表性试答核对边界题、偏科、跳过及基础题弱而难题偶中等情况，明确难度层门槛配置。任何规则变化产生新 `scoring_version`，保留旧结果，不静默重算。

### 评估充分度

第一版使用完成率、各维样本量和难度覆盖，输出高、中、低或不足的评估充分度，以及可读原因。这是产品规则提示，不是统计置信区间，也不是答题真实性证明；首轮不展示未经校准的 72% 等精确可信度。

示例：语境推断完成 6 题、答对 5 题；篇章理解跳过 4 题，因此暂不确定篇章等级，建议补测。自评差异只作为解释信息，不直接降低充分度。

题目出现争议或答案需要修订时，记录影响的题目版本与评测结果。旧结果保留原评分依据并加影响提示；复核或补测另存结果，不能悄悄改写历史等级。

## 推荐与表现回流

### 学习队列

推荐以任务为单位，明确哪些是完整篇章、专项练习或复习。70% 主线、20% 补强、10% 挑战是题库和课程充足时的滚动目标，不把三张卡片称为已满足比例，也不将十个任务称为十篇不同全文。

队列记录学习者、任务身份、类别、能力目标、推荐原因、顺序、内容版本和完成状态。初期只生成当前可供执行的短队列；补强优先匹配薄弱维度，不只是机械降低一档。L1 没有更低等级时仍可做 L1 专项补强；L3 没有 L4 时使用 L3 的新材料挑战。

审核合格的内容不足时，返回实际队列和缺口说明。已完成文章只有在明确标为复习、具有新的训练目标时才再次出现；同一任务不因刷新重复入队。推荐执行情况可统计，不虚构尚未学习的队列结果。

### 独立与辅助表现

新训练记录首次判断、首次判断前是否查看答案性释义或提示、后续改答、有效证据覆盖、核心与迁移结果，以及理由复核状态。现有原文点读不一律当作辅助：读原文是任务的一部分，查看释义和答案性提示则单独记录。

学习报告分别呈现首次独立表现与辅助后完成表现。完成学习仍有价值，但不能用最终全部答对替代首次能力测量，也不能把提示使用率直接当作降级触发器。

当前能够可靠回流的是有规则依据的词义判断、证据覆盖和相应迁移任务结果。句式、篇章和翻译能力只有新增对应题型与合格评分依据后才更新。新事件才使用新字段，旧事件缺少的辅助信息标为未知，不追写或猜测。

### 等级校准

第一轮只调整推荐，不启用自动升降级。积累跨材料、跨日期的独立表现后，先做影子计算：生成拟调整方向和理由，但不修改用户主等级，核对规则是否造成误升或误降。

动态规则必须满足最低独立样本数、涉及不同材料、覆盖关键维度、冷却期和可追溯理由。附件中的 3 篇均分 80、2 篇均分 50 等只能作为试行候选条件，不能用于我们当前没有文章百分制总分的训练。人工或再次测评确认后的结果单独保存。

## 技术架构和数据模型

沿用 React / TypeScript → FastAPI → SQLAlchemy / SQLite。正式评测与推荐建立独立领域模块，不把评分、选题和调级逻辑塞入 `App.tsx` 或继续扩大 `main.py`。新接口沿用现有响应契约、请求期限及错误恢复方式。

| 拟新增模型 | 主要职责 |
| --- | --- |
| AssessmentQuestionRevision | 不可变题目版本及审核依据，服务端持有答案 |
| AssessmentSession | 学习者、冻结试卷、状态版本、保存位置、作答和辅助记录 |
| AssessmentReceipt | 同会话幂等提交收据，防止保存或交卷重复生效 |
| AssessmentResult | 不可变结果、分维样本、题库与评分版本、充分度原因 |
| AbilityProfile | 当前起点及六维汇总，保留观测来源、时间和数量 |
| RecommendationPlan | 有身份的队列及推荐理由，关联内容版本 |
| AbilityObservation | 从题目或训练事件产生的能力观测，来源去重 |

建议模块边界：`backend/domain/assessment.py` 管理测评状态；`backend/domain/ability.py` 管理画像规则；`backend/domain/recommendation.py` 管理队列；对应路由独立注册。前端将测评流程、结果页、队列和能力面板拆为组件，并扩展 `types.ts`、`contracts.ts`、`api.ts`。

已实现创建 `/api/v1/assessments`、读取 `/api/v1/assessments/{id}`、提交 `/api/v1/assessments/{id}/commands`、档案测评历史 `/api/v1/profiles/{id}/assessments`、可用性 `/api/v1/assessments/availability`，以及课程标定 GET / PATCH `/api/v1/admin/lessons/{id}/ability`。C 增加能力档案 GET `/api/v1/profiles/{id}/ability`、推荐队列 GET / POST `/api/v1/profiles/{id}/recommendations`、任务开始 POST `/api/v1/profiles/{id}/recommendations/{task_id}/start`。

当前正式能力档案是从不可变 AssessmentResult 和冻结试卷重建的只读投影，未另建可被随意改写的主等级表。D 使用独立的 StageObservation 保存学习模式中的首次阶段行为，不将其写入正式能力档案。优先采用最近合法且样本充分的正式结果；较新不足结果保留在历史中，不冲掉既有有效依据。仅有不足的正式结果时保留实际样本，未达到每维最低作答量的分数为 null；PILOT 始终单独显示。

推荐采用追加的 RecommendationPlan、当前 RecommendationHead、稳定 RecommendationTask 和 LearningPathReceipt。GET 不生成或更新记录；POST 要求 Idempotency-Key，相同起点和内容复用当前计划，包括空计划。同一任务唯一关联训练会话，状态从该会话派生，不能由同课另一训练冒认完成。新开始严格验证当前发布、审核与能力标定版本；已有会话继续冻结版本，不因后来的改稿、下架或重标定被封死。

课程能力标定 PATCH 新增必填 expected_content_version，取标定 GET 的 current_content_version，同时校验原有 expected_version。旧标定不补造版本绑定，内容修改后 valid_for_content=false；真实教研重新确认后才参与推荐。

测评命令采用 SAVE_ANSWER、SKIP_QUESTION、COMPLETE_ASSESSMENT、ABANDON_ASSESSMENT，要求 `expected_state_version` 和 `Idempotency-Key`。服务端检查题目属于冻结试卷、选项属于该题，以及当前会话状态；发生冲突不覆盖已确认作答。保存状态由服务端响应确认，不显示虚假的已保存。

浏览器仅保存 profile ID、assessment ID 和入口恢复信息。数据库保存已确认答案；恢复时 GET 读取服务端进度。当前未确认编辑在离页时提示，结果未知的命令只允许沿用同标识明确恢复，不盲目重发。

观测写入与完成事件在同一事务内，按来源事件或题目结果唯一去重；重复读取、刷新、重复交卷不增加观测、积分或队列完成次数。`AbilityProfile` 可从观测和结果重建，不能反过来改变原始结果。

## 旧数据保护与暂缓项

新增字段先允许为空，新能力入口按功能开关启用。`school_stage`、`difficulty`、旧课程接口、积分和已有训练会话保留。`completed_levels` 仍表示已完成关卡数量，不重解释为 L1–L3 等级。

原文、题目和评分冻结到各自会话。换新全文、修正注释或更新评分不覆盖历史训练。迁移前备份数据库，并验证已有课程、人工修改、学习档案、训练事件和幂等收据未被修改。

登录权限、AI 开放题评分、自适应测评、自动主等级升降和公网部署不在首轮实施范围。无登录时，档案 ID 只是本地访问入口，不构成身份校验；即使增加 profile ID 检查，也不能宣称实现隐私隔离或跨设备安全找回。

## 分阶段任务与验收

| 阶段 | 开发任务 | 完成门槛 |
| --- | --- | --- |
| A 内容标杆与字段 | 核验《劝学》节选；整理原文范围和释义依据；标定课程能力字段；起草分维题库 | 不虚构审核；题目来源与位置可追溯；FULL 与 EXCERPT 显示准确 |
| B 评测最小闭环 | 题目版本、服务端试卷、保存恢复、交卷、四维结果和试行评分配置 | 经审核的 24 题完整试卷可用；刷新不丢已确认答案；不重复交卷；交卷前不返回答案 |
| C 结果与推荐 | 充分度说明、结果解释、能力档案、首页实际学习队列 | 未测维度显示待评估；推荐原因能追溯；题库不足不伪造比例 |
| D 表现回流 | 独立与辅助事件、能力观测、迁移结果、趋势报告 | 来源唯一去重；历史未知字段不补造；没有评分依据的维度不更新 |
| E 规则校准 | 试测、边界复核、影子调级、补测与内容扩充 | 有代表性试答和可解释规则后，再决定是否开启自动调级 |

建议第一轮交付范围为 A 和 B，先让用户真正完成一次可恢复、可解释的测评；C、D 分别下一轮接入。A 中注释复核和题目起草可以与 B 的数据层及恢复框架并行，正式测评入口必须等题目审核门槛满足后才开放。

本轮已按文件边界并行执行：内容分支起草 48 题及《劝学》核验清单；后端分支实现独立测评领域、增量数据表和路由；前端分支实现试测流程、恢复和结果；主分支完成入口、课程标定、集成、备份与浏览器回归。程序检查不冒充内容人工审核。

每轮按以下检查表验收：

- 内容检查：同字多处不同义、固定词组、异文、注释依据、篇章范围、无教师签名不显示已审。
- 测评检查：分层抽题、选项随机且会话内稳定、ID 判分、非法选项、跨题答案、跳过、全跳过、少样本与评分边界。
- 恢复检查：刷新、关闭后重进、响应丢失、重复交卷、双标签并发、旧题库版本恢复和未确认离页。
- 推荐检查：偏科、新用户、未测评、L1 和 L3 边界、课程不足、完成后回流及明确的复习原因。
- 数据检查：数据库备份、增量迁移、旧会话不改、观测去重、不同评分版本历史不被重算。
- 页面检查：1440、820、390、320px，键盘导航、长题干、保存和错误状态、减少动画、深链接与空结果。

完成 A 和 B 后，由实际试用决定题量、题目难度、耗时和分级阈值是否需要修订，不先承诺测评精度或固定开发天数。
