# 文言·推理：开发任务总纲（融合更新版）

版本日期：2026-10-08。用途：给新 GPT Codex 续开发的产品、教学、架构与验收总指南。

这是对原始工程规格、录音需求、历次用户确认与能力分级融合方案的整合，不替换原始材料。当前代码基线为公开仓库 [pu3163329117-eng/-AI](https://github.com/pu3163329117-eng/-AI) 的 `11fb1fccd7cbd90f83a3c6f082063492f348f586`。实际接手事项见 [交接书](交接书.md)。

## 1. 产品目标

帮助学习者自己读懂陌生文言材料，而不是让 AI 永远代译、代答。产品核心是可解释的推理训练，不是通用聊天或单纯刷选择题。

学习闭环：阅读原文 → 识别本句相对确定的知识与待推断变量 → 可以暂放 → 扩展语境 → 回溯 → 提交证据、理由、判断 → 新材料迁移 → 延迟复习与反馈。

长期关注陌生材料中的有效推理、最小有效提示、跨材料迁移和保留情况。当前积分、规则正确率与学习记录不能直接代替这些指标，尚未建立校准过的完整掌握模型。

## 2. 教学原则与概念边界

- AI 在状态机中工作，不能让模型直接改数据库、跳阶段、发积分、定等级或发布内容。
- 答案正确不等于推理正确，猜中不等于掌握；证据覆盖不等于理由语义有效。
- 允许先暂放，不强迫所有字立即查明；新语境出现后回溯，保留过程。
- 提示由少到多、可追踪，不把直接答案冒充启发。原规格 H0–H6 为教学目标，现有规则提示并不代表完整实现全部策略。
- 迁移重复目标能力，不重复原题；将学习完成、首次判断与真正独立能力测量分开。
- “变量”是本句需要结合语境推断的字词义或关系；“无变量”是本句相对确定，非普遍不变。
- 原文、注释、例证、题目、推理标准均需来源与版本；程序检查不等于真实教师审核。

## 3. 内容与知识库总要求

### 原文与五层语境

完整展示已登记材料范围，并明确 FULL（全文）、CHAPTER（章）、EXCERPT（节选）、PROMPT（题干）。全文标签必须有完整性依据；补齐全文时另建版本，不覆盖节选历史会话。

任意字词点击或连续词组选择，展示：词项定位 → 所在句 → 段落 → 篇章与范围 → 作者、时代及必要背景。所有层级以真实原文和来源支撑，不杜撰背景代替文本证据。

### 字词本句义与相关语境

按每次出现的位置保存词项、词性、本句义、变量分类、推断依据、引用出处和审核状态。同字多处可以不同义；通假、活用、虚词、专名、固定词组、异文与不同注解应有明确边界。

专名内部字可指向整体解释，不为实现“每字有数据”硬造义项。关联其他语境使用真实材料位置、版本和分页；扩充来源后再增加记录，不宣称列举了历史上全部用法。

当前已有 13 单元、3,495 条草稿、4,362 正文字位覆盖。下一步重点是质量核验而非只增长数量：原文准确、定位正确、本句义恰当、注释依据可信、例证能解释区别。草稿始终标为草稿。

## 4. 训练系统要求

后端训练状态机掌握阶段、命令、事件、核验、提示与积分；前端只表达意图。保留核心与迁移、暂放与回看、证据链保存、恢复、复习和完成报告。

答案选项随机但会话内冻结。独立评测采用选项 ID，不按 A/B/C/D 或数组下标判分。原有训练接口保持兼容，迁移需显式契约测试。

推理链逐步从“定位 + 理由 + 结论”扩展到可审核的关系与依据。开放理由允许合理替代路径；没有语义评测依据时保持待复核，不能用字数达标判为正确。

首答、查释义、提示、预设证据、规则回执、反馈与后续重答分别保存。阅读原文不是辅助；首答未记录辅助不等于闭卷独立。历史缺失保持未知，不能反推。

## 5. 能力分级与评测融合

### 分开四种概念

| 概念 | 含义 | 不允许混同 |
| --- | --- | --- |
| 材料范围 | 全文、章、节选、题干 | 不能等同难度 |
| 能力等级 | L1 基础、L2 进阶、L3 高阶的合格测量依据 | 不能由年级、积分或完成量直接得出 |
| 课程标定 | 该内容版本适用的能力档与专项目标 | 不能复制旧 difficulty 当真实校准 |
| 个人练习方向 | 学习者选择更易/难任务 | 不能覆盖正式等级 |

能力六维：字词 vocabulary、句式 syntax、语境 context、篇章 chapter、翻译 translation、迁移 transfer。第一版试测只测前四维；后两维无合格依据时显示待评估。

### A–E 的当前状态与门槛

| 阶段 | 已有交付 | 仍需完成 |
| --- | --- | --- |
| A 内容依据 | 原文范围、知识库草稿、核验清单、课程标定字段、48 题候选池 | 真教师逐项核验、课程版本真实标定 |
| B 评测闭环 | 4 轻自评、24 题分层 PILOT、冻结试卷、保存恢复、幂等交卷、四维结果 | 独立题目审核工作流、合格正式题库、代表性校准 |
| C 能力与推荐 | 正式结果只读投影、试测分开、充分度、持久计划、任务启动及缺口说明 | 内容通过真实审核与标定后验证实际推荐；不伪造队列 |
| D 表现回流 | 首次判断、辅助和重答分离，真实来源观测与趋势 | 后续合格独立专项测量；现有学习记录不充当正式能力 |
| E 规则校准 | 方案已明确 | 代表性试答、边界复核、影子计算、人工/补测确认；未启用自动调级 |

当前 48 道候选题均未完成真实审核，正式入口仍关闭。试卷技术上可运行不代表内容有效、测量精度已验证或时长固定。

### 正式测评与推荐规则

正式测评只提供必要原文和非答案性背景，接口交卷前不得泄露答案、解析或答案性释义。题库修订不改变已创建试卷；评分版本变化不静默重算历史。

输出各维展示、作答、跳过、正确的真实数量及难度覆盖。零样本为 null，全跳过或整维不足不能生成确定等级。充分度是规则解释，不是统计置信区间或答题真实性证明。试行阈值与权重不是已校准参数。

推荐只使用当前发布、审核和标定合格的内容版本。GET 只读，显式 POST 生成计划并要求幂等；任务唯一绑定实际训练，不能由同课其他会话冒认完成。内容不足返回缺口，保留旧练习入口。

70% 主线 / 20% 补强 / 10% 挑战是课程足够时的滚动目标，不把三张卡称为满足比例。L1 补强不必机械降级，L3 挑战用新的 L3 材料；复习重复需新目标与明确理由。

## 6. 下一轮优先实施任务

### P0：题目与内容审核真正闭环

后端建立独立评测题修订、审核记录和发布资格，校验题目维度、档位、选项身份、来源、范围、解释与证据。编辑后审核失效；旧卷冻结；并发旧版本不能覆盖新稿。

前端补教研审核工作台，可筛待审题、预览冻结原文与定位、编辑干扰项/解释、显示版本及审核依据。不会审核的项目明确退回或待确认，不设置“一键全题认证”。

内容先做《劝学》节选标杆和四维三档题库清单，处理来源、歧义、同材题占比、干扰项及难度依据。由真实审核人提供决定；GPT 可准备草稿、指出风险，不能代签。

验收：不合格题不能进入正式卷；题库不足明确关闭正式入口；每个通过项有真实依据和版本；历史恢复不受新版改稿影响。

### P1：真实课程标定与代表性试答

逐课确认能力档、专项标签、材料范围、审核和内容版本。合格课程形成后验证主线/补强/挑战的实际选择和理由；不足仍如实显示缺口。

设计覆盖不同基础、偏科、跳过、临界分、简单题弱而难题偶中的试答方案，收集题目争议、用时、难度分布和替代解释。涉及真实学生前先确认身份与隐私安排；未确认时只使用匿名测试数据。

验收：有可追溯的题目与评分版本、有样本说明，避免从少量开发者试答推断普遍有效。

### P2：Gold Case 与 AI 评测基础

回到原规格范仲淹 Gold Case，校验变量、证据、暂放、回溯、提示梯度、迁移和合理替代推理。不是只把当前选择题包装成已完成 Gold Case。

先实现 ModelProvider 抽象、FakeProvider、结构化输出契约与固定评测集，再选择真实适配器。领域逻辑不绑定供应商；密钥用环境配置，不入库。模型输出做 Schema、引用、泄露、超时与安全校验，失败有规则降级，不让模型获得状态控制权。

AI 上线门槛包括人工标注的正确/错误/替代推理、误区、提示泄露和注入测试；记录 provider/prompt/rubric 版本、调用与成本。原规格 F1、接受率等是目标，不是当前已达指标；确认合适样本和阈值后才能启用语义评分。

### P3：E 影子校准与长期学习

积累跨材料、跨日期、真正可解释的合格表现后，再做只读影子计算，输出拟调整及理由，不修改主等级。检查最低样本、关键维度、材料多样性、冷却期和误升误降；先人工或补测确认，再决定自动化。

完善延迟复习、长期掌握和更丰富句式/篇章/翻译题型。原规格“多次成功、未见材料、低提示、延迟保持”等目标需逐项实现与验证，不能从一次训练完成直接宣称掌握。

## 7. 架构与数据发展原则

当前沿用 React / TypeScript / Vite + FastAPI 模块化单体 + SQLAlchemy / SQLite。将新增模块分为领域、路由、存储、DTO/契约和组件；维护兼容接口，控制入口大文件增长。

所有写命令有版本检查、幂等收据、可追溯事件和事务一致性。内容、原文、题卷、评分和历史观测冻结；读取不偷偷生成数据。新增表/字段先允许兼容旧记录并进行增量迁移，迁移前一致性备份，迁移后核对原记录。

知识图谱描述“知道什么”，推理图描述“如何得出”。先做结构化关系和精确原文引用，不先引入独立图数据库。未来数据量与生产部署有依据后，再迁移 PostgreSQL / pgvector、任务队列及持久存储，不能仅为技术名词重构。

原始规划的 Taro 小程序、Flutter、家长/老师周期报告、完整 RAG、长期 Planner 和 A/B 提示仍是后续产品化候选，不是本轮承诺。历史 12 周排期不自动成为新开发日期。

## 8. UI、页面布局与交互要求

黑白、克制、文字优先，建立统一字号、行高、间距、按钮层级与容器宽度。训练页重点是正文、问题和证据，辅助区不挤压正文；窄屏改上下布局。长文与长题干不截断关键信息。

导航深链接、返回与刷新不空白；加载、无数据、缺口、异常分开显示。所有“已保存”必须基于服务器确认。失败可重读，结果未知可同标识恢复；未确认编辑离页提示。

动画短且有目的，遵从 `prefers-reduced-motion`，不阻挡保存、输入和阅读。按钮、字词、标尺、折叠区可键盘操作，焦点清楚；不能只靠颜色表达审核/正确/错误。

验收宽度 1440、820、390、320px；覆盖真实长内容、字体间距、行宽、侧栏、触达、无横向溢出、空队列、接口错误、刷新和响应丢失。截图不能代替完整业务走查。

## 9. 并行开发组织

用户要求分支协作，推荐主集成 + 后端 + 前端 + 内容核验。开始时明确同一契约、接口、状态和文件责任；没有独立 worktree 时尤其避免多代理同时编辑入口文件。

分支交付代码、测试、契约变更、迁移影响、内容依据与未决项；主代理统一集成、数据库保护、浏览器验收和文档。不要让“分支说完成”代替最终运行验证。新分支默认 `codex/` 前缀，除非用户指定。

## 10. Definition of Done

每轮需满足适用条件：

- 真实前后端与数据库闭环，且加载/错误/空态可用。
- 新逻辑有单元、API、契约与风险相关恢复测试。
- CAS、幂等、来源去重、事务回滚、旧版本与旧数据回归通过。
- 正式内容有真实来源和审核依据；未审项不冒充通过。
- 1440 / 820 / 390 / 320px 与键盘、减少动画实测。
- 数据迁移有备份和完整性/既有记录核对；普通测试不连接运行库。
- AI 变更有固定评测和降级；未实现 AI 不宣称模型评分。
- 代码、日志、种子与历史不泄露密钥、真实个人资料或运行库。
- 更新执行计划、接口与验收记录，报告剩余限制。
- 合并前无未解决的阻断问题；公开源码更新先审核差异与排除项。

当前自动回归基线：256 后端、68 前端、生产构建通过。接手后应重跑，不能将历史记录当新改动验收。

## 11. 暂缓与另需确认事项

用户明确暂缓登录与权限，因此不在本轮抢做；但无认证服务不得直接公网开放管理接口。公开仓库不代表应用已安全生产上线。

公网部署地区、域名、费用、持久数据库、访问可靠性与未成年人数据安排另行确认。不要继续承诺 Vercel 临时 SQLite 为正式部署，也不能保证未经验证的“不开代理访问”。

真实试点前需确认教材/题目版权、审核人与纠错责任、模型数据保留政策、学习数据保存/删除及必要授权。跨设备同步、付费、老师家长权限、自适应测评、自动调级和大规模微调均不是当前完成项。
