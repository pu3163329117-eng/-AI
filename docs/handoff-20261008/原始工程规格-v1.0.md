## 0. 文档使用方式

本文不是概念方案，而是项目的工程母版。Codex 应按以下顺序使用：

1. 先建立仓库、共享类型、数据库和 Training Engine；
2. 再实现 Gold Case 的端到端闭环；
3. 通过固定 Eval 后再扩展内容生产、个性化与多端；
4. 所有 AI 输出必须经过结构化 Schema、权限控制和可追踪记录；
5. 未经教研审核的 AI 生成内容不得直接发布给学生。

本文中的技术选型是 V1 基线。依赖版本须在项目初始化时锁定，并通过 ADR（Architecture Decision Record）记录变更，禁止在业务代码中直接绑定单一模型厂商。

## 1. 产品定义

### 1.1 一句话定义

一个通过“梯度训练、语境推理、个体诊断和跨文本迁移”，最终教会中学生独立读懂陌生文言文的 AI 学习智能体。

### 1.2 要解决的问题

传统题库通常只记录学生“哪道题答错”，翻译器只给结果，聊天机器人则容易直接解释答案。该产品需要记录并训练：

- 学生能否区分可积累的“普遍量”和必须结合语境判断的“变量”；
- 遇到未知词时是否会暂放，而不是停止阅读或立即查答案；
- 能否利用句内结构、句间关系、人物行为和篇章主旨逐步收敛候选解释；
- 学生在哪一步发生认知断点，以及最小有效提示是什么；
- 同一能力换到陌生文本后能否独立使用。

### 1.3 成功定义

产品成功不等于题目完成量、答题时长或对课内篇目的记忆。V1 的北极星指标为：

> 学生在未见文本中，以不高于 H1 的提示等级，完成目标推理链的比例。

配套指标：

- `independent_transfer_rate`：陌生文本独立迁移成功率；
- `median_min_effective_hint`：最小有效提示等级中位数；
- `defer_then_resolve_rate`：暂放后利用新增证据正确回溯的比例；
- `reasoning_validity_rate`：答案正确且证据链有效的比例；
- `delayed_retention_rate_7d`：7 日延迟保持率；
- `direct_answer_exposure_rate`：完整答案暴露率，V1 目标低于 15%。

### 1.4 非目标

V1 明确不做：

- 泛学科 AI 家教；
- 搜题、拍照秒出答案或全文自动翻译器；
- 以聊天框为首页的通用 AI 助手；
- 一次覆盖全学段、全教材、全题型；
- 无教研审核的自动内容发布；
- 用一个总分替代能力结构；
- 让 LLM 自由决定教学状态和掌握判定；
- 首期引入复杂微服务、Kubernetes 或独立图数据库；
- 用学生完整聊天原文充当长期记忆。

## 2. 核心教学协议 v0.1

### 2.1 概念定义

#### 普遍量（Constant）

可跨文章复用、可积累、可迁移的知识或策略，例如：

- 高频实词义项、虚词用法；
- 通假字、古今异义、词类活用；
- 判断句、倒装、省略等句法规则；
- 断句线索、人物关系识别；
- “先确定已知”“未知暂放”“用后文反推”等阅读策略。

普遍量必须对应一个 `knowledge_unit`，并记录证据、来源、适用范围与学生掌握度。

#### 变量（Variable）

必须依赖当前文本才能确定的内容，例如：

- 某字在本句的具体义项；
- 被省略的主语或宾语；
- 指代对象、人物行为动机；
- 句间逻辑、作者态度和篇章主旨。

变量必须有候选集、证据约束、标准推理路径和可接受的替代推理路径。

#### 暂放（Defer）

学生当前证据不足时，主动保留变量并继续阅读。暂放不是跳过学习，而是创建一个待回溯任务：

```text
变量出现 → 证据不足 → 标记暂放 → 继续获取语境 → 触发回溯 → 更新判断
```

#### 语境推理（Contextual Reasoning）

按最小必要范围释放信息：

1. 词内/搭配；
2. 句内语法；
3. 相邻句；
4. 段落人物行为；
5. 篇章主题；
6. 跨文本知识。

不得一开始就释放全文翻译。

#### 梯度提示（Hint Ladder）

提示只增加刚好足够的新信息。系统记录学生首次成功所需等级，而不是仅记录是否答对。

#### 迁移（Transfer）

重复的不是原题，而是能力。迁移任务必须与学习材料在表层词句或篇章上有差异，但共享目标知识或推理策略。

### 2.2 教学闭环

```text
识别已知
  → 标记未知变量
  → 初次推断或暂放
  → 获取新语境
  → 回溯变量
  → 陈述答案与依据
  → 评价答案和推理
  → 最小必要提示
  → 再推理
  → 近迁移
  → 远迁移
  → 延迟复习
```

### 2.3 掌握标准

一个知识点或策略仅在以下条件全部满足时进入 `MASTERED`：

- 至少 3 次有效成功；
- 至少覆盖 3 个不同语境，且至少 1 个为陌生文本；
- 最近 2 次提示等级不高于 H1；
- 至少 1 次能说出有效证据，而非猜测；
- 至少 1 次延迟复习间隔大于等于 24 小时；
- 当前掌握置信度下界达到阈值（V1 默认 0.75，可配置）。

答对但猜测不得计为完整成功；教师可人工覆盖掌握状态，但必须记录理由和审计日志。

## 3. 用户、角色与核心场景

### 3.1 角色

| 角色 | 核心目标 | 权限边界 |
|---|---|---|
| 学生 | 学会独立阅读陌生文言文 | 只能访问已发布内容和自己的画像 |
| 教研老师 | 制作、审核、发布训练单元 | 可编辑内容；发布需具备 reviewer/publisher 权限 |
| 任课老师 | 布置训练、查看班级与个体报告 | 不可修改平台标准答案，除非兼具教研角色 |
| 家长 | 查看孩子的阶段性报告 | 只读且需绑定授权，不展示敏感原始对话 |
| 运营 | 管理班级、活动和内容上下架 | 不可查看学生自由文本原文，除授权工单外 |
| 管理员 | 租户、角色、审计与系统配置 | 高风险操作必须二次确认并留痕 |

### 3.2 核心用户故事

#### S1：今日训练

学生进入“今日训练”，系统依据复习队列、薄弱能力和内容前置关系生成 10–15 分钟训练。学生主要在“文言推理台”完成结构化交互。

#### S2：未知暂放与回溯

学生遇到“从”无法判断，选择暂放；读到“为执经讲解”后系统提示有新证据，学生回看并重新判断“从”的意义。

#### S3：开放答案诊断

学生给出翻译或依据。Evaluator 区分“答案正确且证据有效”“答对但猜测”“句法错误”“没有利用后文”等类型，并由 Training Engine 决定下一步。

#### S4：迁移挑战

学完一个推理策略后，系统换用未见句子测试同一能力，避免重复记忆答案。

#### S5：教研生产

教研上传 DOCX/PDF，Content Agent 生成篇章拆分、知识点、变量、Reasoning Graph、Hint Ladder 和迁移候选。教研逐项审核后发布。

#### S6：教师报告

老师看到的不是“做错 8 题”，而是“该生连续三次未利用后句反推实词义，需要 H3 才能定位人物关系”。

## 5. Training Engine

### 5.1 设计原则

- 状态流转由服务端确定性代码控制；
- LLM 只返回结构化建议，不可直接修改会话状态；
- 所有命令带 `idempotency_key`；
- 每次状态变更有事件、有版本号、可重放；
- 同一训练会话只允许一个活动写入者，使用乐观锁；
- 客户端断线后从服务器快照恢复。

### 5.2 状态定义

```ts
type TrainingState =
  | 'SESSION_CREATED'
  | 'TARGET_SELECTED'
  | 'CONTEXT_PRESENTED'
  | 'KNOWN_ITEMS_CONFIRMED'
  | 'VARIABLE_PRESENTED'
  | 'AWAITING_INITIAL_ATTEMPT'
  | 'VARIABLE_DEFERRED'
  | 'CONTEXT_EXPANDED'
  | 'VARIABLE_REVISITED'
  | 'AWAITING_REASONING'
  | 'EVALUATING'
  | 'HINT_OFFERED'
  | 'HINT_PRESENTED'
  | 'ANSWER_VALIDATED'
  | 'TRANSFER_PRESENTED'
  | 'TRANSFER_EVALUATING'
  | 'REVIEW_SCHEDULED'
  | 'SESSION_COMPLETED'
  | 'SESSION_ABANDONED';
```

### 5.3 核心命令

```ts
type TrainingCommand =
  | { type: 'START_SESSION'; unitId: string }
  | { type: 'CONFIRM_KNOWN'; knowledgeUnitIds: string[] }
  | { type: 'SUBMIT_ATTEMPT'; answer: AnswerInput; evidenceIds: string[] }
  | { type: 'DEFER_VARIABLE'; variableId: string }
  | { type: 'REQUEST_MORE_CONTEXT'; scope?: ContextScope }
  | { type: 'REVISIT_VARIABLE'; variableId: string }
  | { type: 'REQUEST_HINT' }
  | { type: 'SUBMIT_REASONING'; claim: string; evidenceIds: string[] }
  | { type: 'CONTINUE_TO_TRANSFER' }
  | { type: 'END_SESSION' };
```

### 5.4 状态转移表（节选）

| 当前状态 | 命令/条件 | 下一状态 | 副作用 |
|---|---|---|---|
| SESSION_CREATED | START_SESSION | TARGET_SELECTED | 读取学生画像、内容版本 |
| TARGET_SELECTED | 自动 | CONTEXT_PRESENTED | 创建首屏上下文快照 |
| VARIABLE_PRESENTED | SUBMIT_ATTEMPT | EVALUATING | 调用规则或 Evaluator |
| VARIABLE_PRESENTED | DEFER_VARIABLE | VARIABLE_DEFERRED | 创建 deferred item |
| VARIABLE_DEFERRED | 新证据达到触发条件 | CONTEXT_EXPANDED | 释放最小新语境 |
| CONTEXT_EXPANDED | REVISIT_VARIABLE | VARIABLE_REVISITED | 记录回溯行为 |
| EVALUATING | 正确且证据有效 | ANSWER_VALIDATED | 更新 attempt 与 mastery evidence |
| EVALUATING | 错误且可提示 | HINT_OFFERED | 选择最小提示等级 |
| HINT_PRESENTED | SUBMIT_ATTEMPT | EVALUATING | `attempt_no + 1` |
| ANSWER_VALIDATED | 有迁移任务 | TRANSFER_PRESENTED | 选择未见/低相似素材 |
| TRANSFER_EVALUATING | 结束 | REVIEW_SCHEDULED | 更新 Student Model |
| REVIEW_SCHEDULED | 自动 | SESSION_COMPLETED | 写报告与会话摘要 |

非法命令返回 `409 INVALID_STATE_TRANSITION`，不得由客户端猜测修复。

### 5.5 选择下一任务的 V1 策略

候选任务过滤：

1. 内容已发布且适配年级；
2. 前置知识满足或属于诊断模式；
3. 学生未在最近 14 天见过相同 passage；
4. 版权/租户/班级范围允许；
5. 排除已完成且尚未到复习时间的任务。

打分：

```text
score = 0.35 * due_review
      + 0.25 * target_weakness
      + 0.15 * prerequisite_fit
      + 0.15 * novelty
      + 0.10 * teacher_priority
      - repetition_penalty
```

V1 使用可解释规则，不用 LLM 直接规划课程。

## 6. Agent 架构与契约

### 6.1 总体结构

```text
Student Client
      │
      ▼
Training Engine ─── Student Model Store
      │
      ▼
Agent Orchestrator
      ├── Teacher Agent
      ├── Diagnose Agent
      ├── Reasoning Agent
      ├── Content Agent
      ├── Evaluator Agent
      └── Student Model Agent
             │
             ▼
         Model Router
```

六个 Agent 是职责边界，不要求六次模型调用。V1 应尽量用规则、同一次结构化调用或异步批处理完成，避免“多 Agent 为了多 Agent”。

### 6.2 Teacher Agent

职责：将 Engine 决策表达成适龄、简短、启发式的教师话语。

输入：

```json
{
  "state": "HINT_PRESENTED",
  "training_goal": "利用人物关系推断实词义",
  "visible_context": ["学者多从质问", "为执经讲解"],
  "current_variable": "从",
  "hint_level": 2,
  "diagnosis_code": "MISSED_AGENT_RELATION",
  "student_grade": 9,
  "tone": "calm_concise"
}
```

输出：

```json
{
  "utterance": "看看后面的“为执经讲解”：是谁给谁讲？这能说明两人的关系吗？",
  "ui_action": "FOCUS_EVIDENCE",
  "focus_span_ids": ["span_02"],
  "prohibited_answer_leak": false
}
```

约束：不得改变状态、判定掌握、暴露标准答案或输出内部思维链。

### 6.3 Diagnose Agent

职责：判断“为什么不会”，输出标准误区码和置信度。

V1 误区码：

```text
UNKNOWN_LEXICAL_SENSE
MODERN_MEANING_BIAS
MISSED_SUBJECT
MISSED_OBJECT
MISSED_SYNTAX_STRUCTURE
MISSED_AGENT_RELATION
IGNORED_LATER_CONTEXT
IGNORED_PASSAGE_THEME
INVALID_EVIDENCE
CORRECT_BUT_GUESSING
READING_COMPREHENSION_GAP
LOW_EFFORT_OR_RANDOM
INSUFFICIENT_DATA
```

输出必须包含 `diagnosis_code`、`confidence`、`supporting_observation_ids` 和 `recommended_hint_skill`。低于 0.65 时返回 `INSUFFICIENT_DATA`，禁止伪精确。

### 6.4 Reasoning Agent

职责：为内容生成或补全合法 Reasoning Graph；运行时只做路径匹配/补充，不向学生暴露模型私有推理。

输出：节点、边、候选解释、支持/排除证据、最低必要语境、可接受替代路径、风险标记。

### 6.5 Content Agent

职责：从文档生成“候选内容草稿”，流程为：

```text
解析文档 → 篇章切分 → 句/词标注 → 考点候选
→ 常量/变量候选 → Reasoning Graph → Hint Ladder
→ Rubric → 迁移候选 → Schema 校验 → 教研审核
```

任何模型生成字段均标记 `source=ai_generated` 和 `review_status=pending`。

### 6.6 Evaluator Agent

运行时评价标签：

```text
CORRECT_REASONING
CORRECT_BUT_GUESSING
PARTIALLY_CORRECT
WRONG_KNOWLEDGE
WRONG_CONTEXT
WRONG_SYNTAX
WRONG_REASONING
INSUFFICIENT_EVIDENCE
UNSCORABLE
```

必须返回：

- `label`；
- `score`（0–1）；
- `matched_rubric_items`；
- `misconception_codes`；
- `evidence_quality`；
- `next_action_recommendation`；
- `confidence`。

规则能处理的选择、断句和标准化答案优先走规则；开放翻译与理由才调用模型。低置信度结果不得进入掌握证据，可标记人工抽检。

### 6.7 Student Model Agent

异步汇总事件，将多次尝试压缩为结构化长期画像；不保存“昨天说了什么”的冗长自然语言，而保存：

```text
目标能力 + 成功/失败 + 提示等级 + 语境新颖度
+ 证据质量 + 误区 + 时间衰减 + 内容难度
```

不得由单次 LLM 调用直接覆盖掌握值。它只生成候选摘要，数值更新由确定性算法完成。

## 7. 模型路由与 Provider 抽象

### 7.1 路由层级

| 层级 | 实现 | 任务 |
|---|---|---|
| L0 | 规则/程序 | 状态机、答案匹配、断句比对、复习调度、权限 |
| L1 | 低延迟模型 | 分类、简单误区、短 Hint 改写、轻量抽取 |
| L2 | 主 Tutor 模型 | 开放回答评价、个性化教学表达 |
| L3 | 强推理模型 | 内容生产、复杂 Reasoning Graph、疑难诊断 |
| E | Embedding/Reranker | 检索、相似度、迁移题去重 |

### 7.2 路由决策

`ModelRouter.route(task, risk, latency_budget, cost_budget, tenant_policy)` 返回 provider、model、超时、重试和降级策略。

- 学生同步请求默认总预算 4 秒，首字/首事件预算 1.5 秒；
- 内容生产异步任务可用 L3；
- 高风险评价若首模型置信度低，可二次仲裁；
- provider 故障时按允许清单降级；
- 不允许降级到未通过未成年人数据审查的 provider；
- 所有 prompt 使用版本号，不在代码中散落长 Prompt。

### 7.3 Provider 接口

```python
class ModelProvider(Protocol):
    async def generate(self, request: GenerateRequest) -> GenerateResponse: ...
    async def generate_structured(self, request: StructuredRequest[T]) -> T: ...
    async def embed(self, request: EmbeddingRequest) -> EmbeddingResponse: ...
    async def rerank(self, request: RerankRequest) -> RerankResponse: ...
    async def moderate(self, request: ModerateRequest) -> ModerateResponse: ...
    async def health(self) -> ProviderHealth: ...
```

统一错误：`PROVIDER_TIMEOUT`、`RATE_LIMITED`、`INVALID_OUTPUT`、`SAFETY_BLOCKED`、`PROVIDER_UNAVAILABLE`。适配器负责将厂商错误映射到统一错误，不得把 SDK 类型泄漏到领域层。

### 7.4 结构化输出防线

每次模型调用依次执行：

1. 输入最小化与敏感字段移除；
2. Prompt/Schema 版本固定；
3. JSON Schema 校验；
4. 领域校验（ID、枚举、引用存在性）；
5. 答案泄露检查；
6. 安全审核；
7. 失败时一次修复重试；
8. 再失败则降级为规则模板或人工队列。

## 8. Knowledge Graph + RAG

### 8.1 V1 方案

V1 使用 PostgreSQL 邻接表 + `pgvector`，不立即部署 Neo4j。原因：当前数据规模可控、事务与版本审核更重要、团队运维成本更低。达到以下任一条件再评估独立图数据库：

- 图节点超过 500 万；
- 3 跳以上在线图查询 P95 持续超过 150 ms；
- 教研需要复杂路径探索且 SQL 难以维护。

### 8.2 节点类型

```text
CHARACTER         字
LEXEME            词/短语
SENSE             义项
GRAMMAR_RULE      语法规则
SENTENCE_PATTERN  句式
READING_STRATEGY  阅读策略
PASSAGE           篇章
SENTENCE          句子
PERSON            人物
EVENT             事件
THEME             主旨
QUESTION_TYPE     题型
ABILITY           能力
MISCONCEPTION     误区
```

### 8.3 边类型

```text
HAS_SENSE, APPEARS_IN, DEPENDS_ON, SUPPORTS, CONTRADICTS,
PREREQUISITE_OF, TRAINS, TESTS, REFERS_TO, ACTS_ON,
CAUSES, CONTRASTS_WITH, EXEMPLIFIES, TRANSFERS_TO
```

所有节点和边具备 `version`、`status`、`source_ref`、`reviewed_by`、`valid_from`。

### 8.4 RAG 检索链

```text
Query normalization
→ tenant/grade/published ACL filter
→ structured graph lookup
→ vector recall
→ rerank
→ evidence bundle
→ context budget trimming
→ Agent
```

检索优先级：人工审核知识 > 官方教材/真题来源 > 已审核解析 > AI 候选。任何回答必须携带内部 `evidence_ids`；学生端是否显示来源由产品策略决定。

### 8.5 内容切分

禁止仅按固定 token 切块。层级为：

```text

```

每个 span 保留原文偏移、标点版本、所属人物/事件和相邻关系，保证断句、回溯和高亮可复现。

## 9. Reasoning Graph

### 9.1 Schema

```ts
type ReasoningNode = {
  id: string;
  type: 'CLAIM' | 'EVIDENCE' | 'CONTEXT' | 'CANDIDATE' | 'RULE' | 'CONCLUSION';
  text: string;
  sourceSpanIds: string[];
  visibility: 'INITIAL' | 'ON_CONTEXT_EXPAND' | 'HINT_ONLY' | 'INTERNAL';
};

type ReasoningEdge = {
  from: string;
  to: string;
  relation: 'SUPPORTS' | 'RULES_OUT' | 'REQUIRES' | 'TEMPORALLY_PRECEDES' | 'REFINES';
  weight: number;
};
```

每张图还需：`target_variable_id`、`accepted_paths`、`minimum_evidence_set`、`common_wrong_paths`、`rubric_version`。

### 9.2 Gold Case 示例：“从”

文本：`学者多从质问，为执经讲解，亡所倦。`

```text
[学者] --人物角色--> [求学者]
[为执经讲解] --行为--> [范仲淹向学者讲解经书]
[求学者 + 讲解关系] --支持--> [跟随/跟从求教]
[来自] --无法解释行为关系--> [排除]
[从 = 跟从求教] --结论--> [句意成立]
```

可接受证据最小集：人物关系 + “为执经讲解”。只选“跟从”但不能给证据，评价为 `CORRECT_BUT_GUESSING`。

### 9.3 Gold Case 示例：“尝推其奉……”

原文断句候选：

```text
尝推其奉以食四方游士 / 诸子至易衣而出 / 仲淹晏如也
```

训练变量包括：`推`、`奉`、`食`、`诸子`、`晏如`、省略主语与因果关系。系统应先使用已知句法和人物关系，再逐步释放注释“晏如：安然、平静的样子”，最后连接到范仲淹乐善好施、先忧后乐的“仁人之心”。该断句、释义和教学路径在发布前必须由教研复核，不能仅凭模型生成上线。

## 10. Hint Ladder

| 等级 | 定义 | 示例（“从”） | 是否影响独立掌握 |
|---:|---|---|---|
| H0 | 完全独立 | 无提示 | 不影响 |
| H1 | 指向关注位置 | “注意‘从’前后分别是谁。” | 轻微 |
| H2 | 提醒调用策略 | “看人物之间是什么关系。” | 轻微 |
| H3 | 释放局部语境 | 高亮“为执经讲解” | 中等 |
| H4 | 缩小候选 | “跟随 / 来自 / 听从，哪个更合适？” | 较大 |
| H5 | 半步推导 | “求学者请教，范仲淹讲经，因此两人是……” | 大 |
| H6 | 完整讲解 | 给出词义、句意与证据链 | 本次不计独立成功 |

升级规则：

- 每次只升一级；
- 新尝试必须发生在提示后；
- 连续无效输入可触发低努力诊断，但不能惩罚性跳级；
- H4 以上记录为强辅助；
- H6 后必须安排近迁移，不可直接结束；
- 学生可主动请求提示，系统不得用诱导文案羞辱学生。

`min_effective_hint` 为该次任务首次产生有效推理的最低提示等级。

## 11. Student Model

### 11.1 四级记忆

| 级别 | 内容 | 生命周期 |
|---|---|---|
| Working Memory | 当前题、当前变量、可见证据 | 单次任务 |
| Session Memory | 本轮目标、尝试、Hint、阶段摘要 | 单次会话 |
| Learning Memory | 掌握度、误区、迁移和复习记录 | 长期 |
| Profile Memory | 年级、教材、目标、可访问性偏好 | 长期，用户可修改 |

### 11.2 掌握模型

V1 采用可解释的 Beta 证据模型，并为每个 `student × knowledge_unit/ability` 存储 `alpha`、`beta`：

```text
weighted_success = correctness
                 × evidence_quality
                 × novelty_weight
                 × hint_weight
                 × difficulty_weight

alpha += weighted_success
beta  += 1 - weighted_success
mastery_mean = alpha / (alpha + beta)
```

建议 `hint_weight`：H0=1.0、H1=0.9、H2=0.75、H3=0.55、H4=0.35、H5=0.15、H6=0。参数必须配置化并通过 Eval 校准。

### 11.3 画像维度

- 知识：实词、虚词、古今异义、词类活用、句式；
- 技能：翻译、断句、句意、篇章理解、比较阅读；
- 推理：句内、句间、篇章、人物关系、主题验证；
- 策略：暂放、回溯、排除、证据引用、自检；
- 迁移：近迁移、远迁移、陌生文本独立阅读；
- 误区：现代义偏误、主语识别、后文忽略等。

### 11.4 复习调度

V1 初始间隔：10 分钟、1 天、3 天、7 天、14 天、30 天。成功且提示不高于 H1 时升级；强提示或失败时缩短。任务选择以能力为主，可换文本，禁止机械重复完全相同题面。

- 管理后台强制 MFA；
- 高风险操作写不可变审计日志；
- 跨租户查询在 repository 层强制 `tenant_id`，并通过测试验证。

### 16.2 数据保护

- 传输 TLS，敏感字段与对象存储服务端加密；
- PII 与学习行为逻辑分离，以内部 ID 关联；
- 密钥仅存密钥管理服务，不进入仓库和日志；
- 可配置保存期限、导出、撤回同意和删除/匿名化；
- 模型请求只发送完成任务所需上下文；
- 未经明确合规配置，不将学生数据用于 provider 训练；
- 生产数据禁止复制到开发环境。

### 16.3 AI 安全

- 上传文档、RAG 文本和引用会话全部视为不可信数据；
- 防 Prompt Injection：数据与指令分区，工具白名单，内容不可调用管理工具；
- 输出做答案泄露、辱骂、自伤、色情、歧视和不适龄内容检测；
- 不展示内部 Chain-of-Thought；仅展示经审核的简洁教学依据；
- 模型不可执行 SQL、发布内容、修改画像数值或越权查询；
- 异常答案提供“报告问题”，进入教研队列；
- 内容发布必须通过来源、版权、事实、答案、提示和迁移六项审核。

### 16.4 文件安全

- 白名单：DOCX、PDF；
- 限制大小、页数和解压后体积，防 Zip Bomb；
- MIME 魔数检查，病毒扫描；
- 文档解析在隔离 Worker；
- 原文件和解析产物带 SHA-256；
- OCR/解析文本只生成草稿，不自动发布。

## 17. Gold Training Case

### 17.1 来源

首个样板取自用户提供的 2025 锦州名校期末真题材料：

- 甲：《岳阳楼记》“古仁人之心”段；
- 乙：《宋史》范仲淹相关材料；
- 题型：词义/用法、翻译、断句、人物精神概括。

### 17.2 训练目标

1. 理解“普遍量靠积累，变量靠语境推理”；
2. 遇到未知实词能暂放；
3. 利用人物关系与后句行为推断“从”；
4. 利用句法和事件关系理解“推其奉以食四方游士”；
5. 将多个具体事件归纳为“仁人之心”；
6. 在陌生文本中迁移“根据后文行为反推词义”策略。

### 17.3 内容拆分

普遍量候选：

- `以` 的相关用法；
- 判断/省略结构；
- 人物—行为—对象关系；
- 断句中的主语切换与句意完整性；
- “具体事例 → 人物品质”的概括方法。

变量候选：

- `从` 的语境义；
- `质问` 的古义；
- `推`、`奉`、`食`；
- `诸子` 指代；
- `晏如` 的状态及其与前文的关系；
- `感激` 的古义；
- `未报`、`请间`、`循行`、`振`；
- 事例如何共同支持“先忧后乐/仁人之心”。

### 17.4 必测完整交互

```text
呈现“学者多从质问”
→ 学生对“从”不确定
→ 允许暂放
→ 释放“为执经讲解”
→ 提醒回溯
→ 学生选择义项并选证据
→ Evaluator 区分推理与猜测
→ 必要时 H1-H6 递进
→ 给新句做近迁移
→ 给不同篇章做远迁移
→ 安排 1 日复习
```

### 17.5 Gold Case 交付物

- 原文与偏移稳定的 passage JSON；
- 至少 5 个变量；
- 每个变量 1 张经审核 Reasoning Graph；
- 每个变量 H1–H6；
- 每个开放任务 Rubric；
- 至少 2 个近迁移、2 个远迁移任务；
- 典型正确、猜测、句法错、语境错样例各 10 条；
- 固定端到端测试和 Eval 数据集。

## 18. 测试与 Eval

### 18.1 常规测试

- 单元测试：状态转移、掌握更新、Hint 升级、权限过滤；
- 属性测试：任意命令序列不会产生非法终态、负数 Hint 或重复 sequence；
- 集成测试：PostgreSQL、Redis、对象存储、Provider fake；
- 契约测试：OpenAPI、前端生成客户端、事件 Schema；
- E2E：登录 → 今日训练 → 暂放 → 回溯 → Hint → 迁移 → 报告；
- 迁移测试：数据库 upgrade/downgrade 与种子数据；
- 性能测试：100 并发训练命令、长会话恢复；
- 安全测试：越权、跨租户、上传恶意文件、Prompt Injection、敏感日志。

### 18.2 AI Eval 集

固定 `evals/gold_case_v1`，至少包含：

- 100 条开放回答评价；
- 50 条误区诊断；
- 每级 Hint 各 30 条泄露测试；
- 50 条替代但有效的推理路径；
- 30 条无意义/随机输入；
- 30 条 Prompt Injection；
- 20 条敏感或不适龄内容；
- 20 条 provider 超时/无效 JSON/降级场景。

关键指标：

| Eval | V0 门槛 | V1 门槛 |
|---|---:|---:|
| 评价标签 Macro-F1 | ≥ 0.75 | ≥ 0.85 |
| 有效替代推理接受率 | ≥ 0.85 | ≥ 0.92 |
| 错误推理误接受率 | ≤ 0.10 | ≤ 0.05 |
| H1–H5 直接泄露答案率 | ≤ 0.05 | ≤ 0.02 |
| 结构化输出有效率 | ≥ 0.97 | ≥ 0.99 |
| 安全攻击阻断率 | ≥ 0.95 | ≥ 0.98 |

### 18.3 教学效果试验

V1 小规模试验建议：

- 30–100 名目标年级学生；
- 前测、训练、同构后测、7 日延迟测；
- 对照传统答案讲解或普通题库；
- 主要看陌生文本迁移，而非原题正确率；
- 记录最小有效 Hint 和证据质量；
- 教研抽检所有 H5/H6 会话和低置信评价。

## 21. 验收标准

### 21.1 产品验收

- 首页主入口为“今日训练”，非通用聊天；
- 学生可以主动暂放并在新证据出现后回溯；
- 同一变量支持答案 + 证据提交；
- Hint 严格逐级，不直接跳到解释；
- H6 后自动进入迁移任务；
- 能力报告能解释“哪里不会、为什么不会、需要何种提示”；
- 教研可不改代码完成导入、审核、发布和回滚。

### 21.2 工程验收

- 核心状态机 100% 分支覆盖，非法转移有测试；
- 服务端是训练状态唯一事实源；
- 所有发布内容有版本、审核人和来源；
- API/事件/Agent 输出均有 Schema；
- provider 可用 fake 和第二适配器替换，领域层无需修改；
- 端到端 Trace 可从一次学生操作定位到模型调用和状态变更；
- 跨租户、越权、重放和并发写测试通过；
- 生产日志无 token、密码和未脱敏 PII；
- V1 AI Eval 达标；
- 数据库可从空库迁移并导入 Gold Case。

### 21.3 教学验收

- Gold Case 的常量、变量、图、Hints、Rubric 经至少 2 名教研确认；
- 有效替代推理不会因措辞不同被判错；
- 猜中答案不记为有效推理；
- 迁移题表层不同、目标能力一致；
- 学生面对陌生文本的提升可用前后测验证；
- 所有完整答案暴露均可在事件中追踪原因。

- 初始化 monorepo；

- Passage、Span、Variable、ReasoningGraph、Hint、Rubric、TrainingUnit JSON Schema；

### T02：数据库基线（1–1.5 天）

### T03：Training Engine 纯领域核（2 天）

### T04：Provider 与 Agent 契约（1.5 天）

- `ModelProvider` 接口；

### T05：训练 API（2 天）

### T06：V0 Training Harness（2 天）

交付：

- 文本区、任务区、证据板、暂放区、Hint、迁移；

### T07：Eval Gate（1.5 天）

## 25. 最终工程原则

1. **AI 在状态机里工作，状态机不跟着 AI 走。**
2. **先证明学生如何推出来，再扩充题量。**
3. **答案正确不等于推理正确，猜中不等于掌握。**
4. **重复能力，不重复原题。**
5. **知识图谱记录“知道什么”，Reasoning Graph 记录“怎么得出”。**
6. **长期记忆保存认知状态，不堆积聊天原文。**
7. **所有模型输出都可验证、可追踪、可替换、可降级。**
8. **教研后台与学生端同等重要，未经审核不发布。**
9. **先做模块化单体和 Gold Case，数据证明需要后再复杂化。**
10. **产品最终要教会学生自己读懂，而不是让 AI 永远替学生读懂。**

## 附录 A：Definition of Done

一个开发任务只有在以下条件全部满足时才算完成：

- 功能与验收场景一致；
- 单元/集成/契约测试按风险补齐；
- OpenAPI/Schema/事件有更新；
- 权限、隐私、错误和空状态已处理；
- Trace 能观察关键路径；
- 不在日志、代码和 fixture 中泄露密钥或真实 PII；
- 数据迁移可执行；
