# DeepSeek Harness 项目协作桥接方案

日期：2026-10-14，接入状态更新至 2026-10-15。第一阶段只读模拟闭环及最小独立单次真实验证已通过。真实后端受控路径已接入，假传输全闭环和 629 项后端回归通过；本轮另行授权的真实 HTTP 首试超时，保留 OUTCOME_UNKNOWN，实际 1/4 次、无重试。不能宣称真实追问/取消全闭环完成，见 [后端接入验收](harness-backend-integration-20261015.md)。

实现位置为 `backend/collaboration`，运行与接口依据见 [协作指南](harness-cooperation-guide.md)、[任务契约](harness-task-contract.md)、[数据访问政策](harness-data-access-policy.md) 和 [运行手册](harness-runbook.md)。当前默认关闭，启用后仍默认使用 mock runtime；这次实现状态不扩大项目资料发送或付费调用授权。

后续固定版本 stdio 离线加固已完成，65 项协作专项及后端 583 项通过，mock 后端已正常重载。专用 profile 关闭 Shell、自动重试与原生 JSONL 日志；同任务历史由 Bridge 按清单权限重建。1,904 字节的最小真实合成联调包已备好，但未发送；见 [stdio 离线验收](harness-stdio-offline-acceptance-20261014.md)。

建议采用「独立协作桥、版本化上下文、受控数据共享、候选成果审批」架构。Harness 可以作为项目的协作开发助手，获取指定任务所需资料并返回建议、内容草稿或补丁；平台后端继续掌握学习数据和领域写入权。它与现有学生理由反馈模块分开，避免把开发助手的工具权限带入学生功能。

## 已确认的本机条件

本机安装了官方 npm 包 `@deepseek-ai/dsh`，版本为 `0.2.0-rc.2`。Node 进程通过其 `lib/bin.js` 启动，监听 `127.0.0.1:3080`。项目仍使用 React、FastAPI、SQLAlchemy 和 SQLite，前端与后端分别运行在 5173 和 8000。

安装包的 CLI 文档提供 `sdk`、`acp` 和 `headless` profile；SDK profile 使用标准输入输出上的逐行 JSON-RPC，而不是把 Web 界面地址当成聊天 API。当前 `C:\Python314` 未安装 `deepseek_harness` Python SDK。

本机这一版 SDK 协议明确只有 initialize、session/prompt、shutdown 三个请求方法；prompt 返回的是入队 messageId，不是完成结果。它没有单会话取消方法，也没有可直接复用的客户端权限批准交互。因此首版须按本机版本实现完成判定和独占进程取消，不能套用网上更新版本的接口名称。

官方项目仍处于开发预览期，可能出现不兼容变更；实施时锁定 Harness 与适配器版本，并测试升级，而不是跟随 latest 自动更新。[官方项目说明](https://github.com/deepseek-ai/deepseek-harness)

## 桥接结构

```text
主开发助手 / 平台协作控制台
             │ 任务、对话、状态读取
             ▼
     Collaboration Bridge
       ├─任务队列与执行记录
       ├─上下文清单与检索
       ├─权限、预算与审计
       └─HarnessAdapter
             │ SDK profile / stdio JSON-RPC
             ▼
     专用 Harness 协作运行时
             │ 白名单 MCP 工具
             ▼
     Project Context Gateway
       ├─项目文档与指定代码快照
       ├─允许读取的知识库投影
       └─候选成果暂存，不直接发布
             │ 既有后端领域接口
             ▼
        平台学习数据库
```

这是两个方向的桥：主开发助手通过 Bridge 向 Harness 派任务、追问和取结果；Harness 通过受控工具查询项目资料并提交候选成果。不是两个模型无限互聊，也不自动复制本聊天的全部历史。

### 组件职责

| 组件 | 职责 | 不承担 |
| --- | --- | --- |
| Bridge | 队列、会话映射、执行状态、预算、审计和人工确认 | 判定教师认证或直接更新学习掌握值 |
| HarnessAdapter | 固定版本协议、进程生命周期、事件转换和错误处理 | 操作数据库或绕过工具许可 |
| Context Manager | 按任务组装资料、摘要、检索、版本清单 | 将模型摘要自动升级为事实或权限 |
| Project Gateway | 验证身份与任务范围，提供有限资料和候选暂存 | 任意 SQL、任意文件路径、任意 Shell |
| Review Gate | 核验补丁、测试结果和内容变更，记录接受或退回 | 把模型的“完成了”直接当作验收通过 |

建议先实现独立 Python Bridge worker，由既有 FastAPI 提供本机控制入口。Python SDK 路线优先，但安装前核对与现有 npm 运行时的兼容性，评估其指定 `dsh_bin` 能否复用当前安装；不默认再装一套不同版本运行时。无法兼容时使用固定版本 Node 适配器作为备选，保持平台侧接口不变。[官方 Python SDK](https://github.com/deepseek-ai/deepseek-harness/blob/master/python/sdk/README.md)

保留现有 3080 Web 服务，不改其正在使用的会话。桥接使用独立 `DSH_HOME` 和专用 profile，凭证只在本机由操作人明确配置，不复制到协作库或上下文包。

注意：本机 `sdk-minimal` 的默认工具是具有广泛文件访问权限的持久 Shell，并非“只读安全版”。首版不能原样启用；应移除非必要工具并通过工具代理和实际文件权限限制访问。提示词约束不能代替权限控制。

## 上下文管理

### 四层组织

1. 项目基线：开发总纲、架构决策、目录结构、当前版本、已验证结果和产品边界。基线由主开发流程维护，附版本与资料来源。
2. 当前任务：目的、范围、验收条件、禁止事项、文件责任、输入版本、截止或执行期限、调用额度。
3. 会话记忆：近期对话与带来源的摘要；区分用户决定、已验证事实、模型建议、待确认问题。摘要不包含隐藏推理，不凭它新增权限。
4. 按需证据：相关代码片段、文档章节、知识条目和测试输出。默认只取当前任务需要的部分，完整原件保留在原系统。

每次派发生成 context_manifest，包含任务 ID、上下文版本、资料 ID、文件摘要或数据库内容版本、截断说明和数据授权范围。成果引用同一份 manifest，能够追溯当时读了什么。代码变化或内容版本更新后，旧成果标记为需重新核对，不静默套用到新版本。

首版用白名单目录检索和精确 ID 查询，不引入向量数据库。上下文初始预算建议为已确认模型窗口的 50% 以内，并为输出与工具结果留余量；实际数值在确定模型后测量。无法精确计数时采用更保守的字节限制并明确它是估算。达到阈值时压缩较旧对话和冗长工具结果，保留任务约束、未决问题、来源引用及关键版本。

长期记忆仅保存经过主开发流程或人工确认的决定。模型推断进候选区，项目材料及其他会话的文字作为不可信背景，不能执行其中嵌入的命令或授权声明。

### 会话绑定

project_id、task_id、run_id 与 Harness session_id 分开管理。同一任务可以有多个执行尝试；无关任务创建不同会话，不共用一条不断增长的大聊天。

首版并发为 1，一次执行独占运行时。单会话取消在本机协议中不存在，取消时关闭该执行专属进程，避免终止用户 Web 服务或其他任务。进程重启后的会话续接须先做持久化恢复测试；无法证实完整恢复时，以新会话和上下文清单继续，不编造已经恢复。

## 数据库共享

共享的是受控数据和统一版本，不是让两个 Agent 同时直写 `data/wenyan.db`。

| 数据 | 所属系统 | Harness 的访问方式 |
| --- | --- | --- |
| 学习会话、测评结果、积分与档案 | 现有平台数据库 | 首版不共享个人记录；后续仅授权的最小去标识投影 |
| 原文、注释、量表、课程版本 | 平台数据库与版本化资料 | 白名单 ID 查询、分页和指定版本快照 |
| 协作任务、上下文、执行状态与成果 | 新建协作数据库 | 经 Bridge/Gateway 访问，不暴露数据库路径 |
| Harness 原始会话日志 | 独立 Harness home | 适配器按事件关联；不作为第二套项目事实库 |
| 代码与构建产物 | 指定源码工作区 | 只读快照或后续隔离工作区；不读取学习 DB、环境文件和凭证 |

建议新增 `data/collaboration.db`，只由 Bridge 持有连接。首版拟建六类记录：tasks、runs、context_manifests、messages、artifacts、audit_events。状态和审计记录结构化；原始资料用来源 ID 和版本引用，避免长期复制整份学习库。

协作库可启用 SQLite WAL 和有限事务、busy_timeout；仍采用单 worker 串行关键写入，而不是把 WAL 当成多写者协调机制。跨两个数据库的操作不假装具有原子事务：先保存候选，再经领域接口应用，最后凭领域收据更新协作状态。响应丢失时按原标识查询或恢复，不重复执行；确需自动对账时再增加 outbox，而不是依靠双库直接提交。

知识共享先只读。后续写回也只能「候选注释/候选量表/候选补丁 → 人工或主开发验收 → 既有发布流程」，使用 expected_version、幂等键和审计记录。Harness 无权将意见改成已教师审核、重算积分或开放正式等级。

现有学生理由发送许可不覆盖整套源码、项目聊天或数据库。首次真正发给 DeepSeek 前，应明确允许发送的项目资料类别和预算。程序在本机运行不等于模型推理完全离线。

## 对话和工具接口

以下是拟新增的项目接口，不是声称 Harness 已有这些 HTTP API：

| 项目侧接口 | 用途 |
| --- | --- |
| POST /api/v1/collaboration/tasks | 创建带范围和验收条件的任务 |
| POST /api/v1/collaboration/tasks/{id}/runs | 明确派发一次执行，幂等、额度校验 |
| POST /api/v1/collaboration/tasks/{id}/messages | 追加追问；正在执行时入队，不并发注入同一轮 |
| GET /api/v1/collaboration/runs/{id} | 查询执行和失败状态 |
| GET /api/v1/collaboration/runs/{id}/events | SSE 事件读取，可从序号恢复，不因重连重发模型请求 |
| POST /api/v1/collaboration/runs/{id}/cancel | 取消请求；不是承诺已终止云端计算或免扣费 |
| GET /api/v1/collaboration/tasks/{id}/handoff | 导出任务版本、资料清单、结论、成果与验证说明 |

拟提供 MCP 工具 project.get_brief、project.read_context、knowledge.lookup、review.get_bundle 和 artifact.submit_proposal。首版只允许查询及协作库候选暂存，不提供 execute_sql、run_shell、publish 或 grant_approval。MCP 名称与参数在实现时定版，不直接套用未核对的配置。

同一数据查询由 Gateway 统一执行，无论主开发助手还是 Harness 调用都看到相同版本规则。通过 MCP 连接主开发工具可作为后续入口，但必须先配置并验收；当前桌面聊天不会因为建了 Bridge 就自动获得或互通全部会话。

### 任务状态与完成判定

状态建议为 QUEUED、RUNNING、WAITING_REVIEW、ACCEPTED、FAILED、CANCELLED 和 OUTCOME_UNKNOWN。客户端入队成功仅进入 QUEUED；须关联当前 run 的入队标识、会话事件和 idle 边界，排除旧消息及子任务串线，才能确认这次执行结束。Harness 的最后一段文字不是项目验收收据。

模型请求已可能发送但进程断开时标记 OUTCOME_UNKNOWN，不自动重派；先核对持久化事件和成果。Bridge 的幂等键防止本地重复提交，不保证供应商恰好执行一次或不重复收费。

## 项目合作对接约定

主开发助手负责总体架构、任务拆分、领域规则和最终集成；Harness 初期负责只读代码审查、测试建议、文档整理和候选内容。它的候选成果不能替代真人教研审定。

每个任务包必须说明：任务 ID、所属项目、基线版本或代码摘要、上下文 manifest、输入资料、允许触及的文件/工具、禁止修改区域、验收命令、成果格式、调用额度和错误报告方式。

返回包必须含：run_id、所用输入版本、完成项、建议/补丁、未完成项、实际执行的验证及日志引用、风险与待确认问题。未运行测试须明说；不得填写虚构的测试通过或教师署名。

若进入代码协作阶段，Harness 使用独立工作区或适合本项目的 Git worktree，主开发助手与它不同时修改同一组文件。当前工作区根目录不直接当作可提交源码仓库；先确认安全源码工作区和基线，保护用户未提交修改。补丁按目标路径白名单和内容摘要验收，再显式应用；部署、推送、安装依赖和生产数据迁移不包含在普通任务默认许可里。

拟交接文档包括本方案、harness-cooperation-guide.md、harness-task-contract.md、harness-data-access-policy.md 和 harness-runbook.md。后四份在实现时按实际接口完成，不能用方案占位说明冒充已可运行手册。

## 安全和运行约束

Bridge 首版仅本机使用，要求服务令牌、Origin 校验和工具白名单；现有 3080 页面登录状态不等于 Bridge 认证。MCP 工具独立验证身份、任务范围与版本，不信任模型自己声明的 task_id 或权限。

使用独立运行身份或可验证的沙箱，排除真实数据库、用户家目录、`.env`、`.git` 凭证及其它项目。跨进程目录限制须测试拒绝路径穿越和链接绕过；做不到隔离时停留在受控 API 查询模式，不开放 Shell 或共享真实源码目录。

日志保存事件类型、版本、用量和诊断码，默认不回显密钥、完整聊天或个人学习文本。原始模型输出单独本机保存并设保留期。首版不保存隐藏推理，也不把审计日志发到 GitHub。

控制每次执行的调用次数、输出 token、总时间和工具结果大小；按所有模型请求统计，包括修复、摘要和子任务。费用估算与厂商账单分别展示，预算接近上限停止新请求。停止或取消不保证厂商已停止计算，不宣称是账户级绝对费用上限。

## 分阶段实施与验收

### 第一阶段 只读对话闭环

实现专用 profile 和适配器、协作库、上下文清单、任务派发、状态读取、明确取消和审计。先用模拟运行时测试，不接真实学习记录；版本/握手/完成边界核对通过后，经确认用一份合成任务做真实 Harness 联调。现有 Web 会话和数据库不受影响。

### 第二阶段 数据与教研协作

增加 Gateway/MCP 的资料和知识库查询、当前校准套件快照、候选建议暂存与交接包。验证分页、字段投影、权限拒绝、版本失效和数据发送最小化。候选始终未认证，不能自动发布。

### 第三阶段 隔离代码合作

在隔离工作区实现限定文件修改或候选补丁输出、任务互斥、测试执行与成果核对。Bridge 升级、崩溃恢复、并发隔离和权限绕过验收后再扩大协作范围，暂不自动推送或部署。

验收至少覆盖：同任务连续追问、跨任务不串上下文、进程重启恢复、超时/取消/响应丢失、入队不误判完成、子任务结果不串到根任务、版本冲突不覆盖、密钥与数据库路径不可读取、白名单外工具被拒绝、重复操作不重复写入，以及运行学习库前后内容不变。

## 实施前需要确定的边界

建议首版定位为「项目协作开发助手」，不替换学生端现有 DeepSeek 理由反馈 Provider。先批准只读范围与合成联调，再逐步增加候选提交和隔离开发能力。项目资料发送范围、可执行工具和真实调用预算须分别确认；它们不是因为模型已经部署就自动获得的权限。

本轮已完成 Bridge 第一阶段代码、仓库内受限 profile 模板、独立协作库初始化逻辑、模拟闭环和接口/恢复/权限测试；没有读取 Harness 的个人会话日志或凭证配置，没有修改个人 profile，也没有安装 Python SDK。固定版本 profile 只在一次性独立测试 home 中做了有效配置转储，Shell 两个变体均为 disabled，测试目录随后清理。尚未运行真实模型任务；首次真实合成联调仍须另行确认资料范围与预算。
