## 使用方法

1. 打开 `http://127.0.0.1:5173/#/admin`，选择「AI 样例核对」。仅允许在运行平台的这台电脑上使用；内网和公网地址不能访问此接口。
2. 按目标词或最新意见筛选，选择样例，先核对给定原文、合成学生理由和开发量表。
3. 填写实际署名、所用原典或注本依据、语境充分性及关系判断。可记录替代表达、分歧和建议标签。开发预期默认收起，查看它不等于已经实施盲评。
4. 点击「追加保存意见」，在意见历史中查看记录。更正意见需再追加一条，不删除或修改原意见。

队列的已有意见数量只反映当前套件的记录覆盖，最新意见是最后一条记录，不是多人一致性或通过率。自填署名尚未核验，所有记录保持 `NOT_VERIFIED`。

## 保存与异常恢复

保存绑定套件摘要、输入摘要和当前意见版本。其他页面先写入时返回版本冲突，不覆盖；请复制自己的文本，再重新读取并核对。旧套件意见不混入新套件进度。

发送前浏览器会在本标签页的 sessionStorage 保存原提交标识及意见。网络响应丢失时表单锁定，需主动点击「按原标识确认保存」。刷新后进入同一工作台可恢复该操作，不自动重发；服务端以原标识返回同一条记录，不重复追加。关闭标签页或清除浏览器存储可能丢失该恢复信息，请先处理待确认提交。不要在意见中填写密钥、联系方式或其他个人敏感信息。

浏览器存储不可用时不发送新意见。离开未保存或待确认页面会提示确认；未发送草稿不自动持久化。保存收据已确认但随后详情读取失败时，成功记录保留，页面不会将它误认为新的未确认提交。

## 架构与接口

React 工作台经严格响应契约访问 FastAPI；SQLite 的 `ai_reason_review_notes` 表保存追加记录。唯一约束 `(suite_digest, case_id, revision)` 实现并发版本保护，提交标识和请求摘要实现幂等校验。初始化仅新增此表，不改写原有学习数据。

接口前缀为 `/api/v1/admin/ai-reason-review`：GET `/cases` 读取队列，GET `/cases/{case_id}` 读取材料与历史，POST `/cases/{case_id}/notes` 追加意见。POST 必须携带 `Idempotency-Key`，正文包含 `expected_suite_digest`、`expected_input_digest`、`expected_revision` 和 `fields`。本机来源限制不是生产鉴权，不适用于公网教研发布。

本模块不读取模型密钥、不调用模型、不改写校准样例或运行量表。`reviewer_identity_verified`、`semantic_accuracy_verified`、`may_update_learning`、`live_ai_release_gate_satisfied` 始终为 false。
