# 字词审核和推理证据链验收

2026-10-07。此迭代把现有注释接入人工审核工作流，并保存学习者实际选取的原文证据、推断理由与词义结论。保留黑白界面、历史训练和种子原文，不将覆盖率或非空理由当作教学正确性认证。

## 操作入口

打开 `http://127.0.0.1:5173/`。内容管理中的“字词知识库审核”可按篇、审核状态及字词筛选。选择一处字词，编辑本句义、词性、变量分类、语境依据、来源与注释出处；填写编辑人和说明后保存草稿。实际核对完成后，单独点击“人工审核当前版本”。审核需有来源链接及注释依据，原典正文链接本身不代替释义出处。

训练中选择词义，再到原文使用词组起止选择，将当前选段记为证据，填写至少 5 个字的理由并保存，最后提交判断。点读位置不自动计作证据。进入迁移后须重新选证据和写理由；“回看本次训练的证据与理由”保留两个阶段的记录，复习页打开既有会话也能查看。

## 数据和接口

AnnotationHead 保存当前注释版本，AnnotationRevision 追加修订或审核记录，v0 从原始 KnowledgeOccurrence 读取。编辑不覆盖种子位置、文本或义项键；修改后的版本是草稿，旧审核仍在历史中。版本检查和事务保证陈旧页面不覆盖其他修改，重复的无变化保存不创建新版本。

| 接口 | 用途 |
| --- | --- |
| GET /api/v1/admin/knowledge/annotations | 按 document、status、q、offset、limit 分页筛选 |
| GET /api/v1/admin/knowledge/annotations/{id} | 当前注释及包含 v0 的完整历史 |
| PATCH /api/v1/admin/knowledge/annotations/{id} | expected_version、actor、note 与编辑字段保存草稿 |
| POST /api/v1/admin/knowledge/annotations/{id}/review | 对 expected_version 单独署名审核 |
| POST /api/v1/training/sessions/{id}/commands | SAVE_REASONING 沿用 expected_state_version 和 Idempotency-Key |
| GET /api/v1/training/sessions/{id}/reasoning | 读取追加的推理记录 |

证据位置为同段 `[start,end)` Unicode 码点，最多 80 字；后端从冻结原文生成证据文本，拒绝越界、空白、纯标点及非整数位置。理由限制 5–2000 字，结论必须是冻结会话的选项。证据链包括目标词、材料来源版本、位置及原文、理由、结论、预设线索覆盖标记和 UNREVIEWED 理由状态。

规则只判断选项及预设线索覆盖；分列线索须全部包含在同一选段中。不评估开放理由语义，不因为保存而加分，积分仍只在完整训练完成时结算。选择其他词义后需重新保存匹配结论的链。核心核验通过后锁定当前编辑，迁移清空当前链但不删除旧事件。

## 验证结果

后端完整回归 122 项、前端回归 37 项通过，TypeScript 和 Vite 生产构建通过。新增测试覆盖草稿修订、审核与失效、v0 和追加历史、来源与输入校验、陈旧版本冲突、无变化保存、种子重启保护、字位定位、理由状态、证据各片段覆盖、所有 16 阶段可选原文线索、迁移隔离、幂等收据与只读历史。保存新的词义结论后恢复最新结论，不让较早的错误作答覆盖新选择。

## 当前使用边界

审核署名仍为本地自填，尚无账号认证或教研权限；管理接口不得直接公开。系统检查来源字段及版本，不验证链接内容是否真正支持释义，实际教研人员须逐条核对。没有批量自动审核，也没有将草稿伪装成已审定。

理由尚未接入教师批注或 AI 语义评分。最小证据链是一条目标、证据、理由、结论路径，尚未实现多证据、多关系图编辑。原文与答题快照保持冻结；阅读注释显示当前教研修订层，不代表旧会话当时所读的注释版本重放。训练事件中的证据和理由不随教研编辑改变。

下一步优先安排实际教师审核首批词项，并建立开放理由评测样本；模型 Provider、生产鉴权及持久部署继续按总开发指南执行。
