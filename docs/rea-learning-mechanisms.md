REA 通过 CDP 实际观察了多邻国未登录公开首页。返回中文页面，包含开始学习与已有账户两个入口。证据位于 `output/rea-study-20261015/duolingo-public-evidence.json`，证据 ID 为 `ev_28faa0d2b9fb0e83f18b445eff3b504a82d666d7be2f7b52784f83fe0d37012a`。本次采集没有开启脚本源码、存储键、存储内容或原始网络响应体采集；CDP 连接前的网络活动不在证据中。该证据只支持首页观察，不代表已经还原其登录后课程、原生应用或推荐算法。

下列学习机制来自官方公开说明，而非首页观察得出的内部实现结论：

| 产品与依据 | 可参考的机制 | 与文言推理平台的结合 |
| --- | --- | --- |
| [Duolingo 间隔复习说明](https://blog.duolingo.com/spaced-repetition-for-learning/) | 分散复习、根据表现安排练习与错题回顾 | 保留语境与推理证据，而不只重复正确选项；后续再接持久化调度 |
| [Busuu 词汇复习说明](https://help.busuu.com/hc/en-us/articles/16941990776593-How-can-I-review-my-vocabulary) | 回顾词汇、例句；闪卡先隐藏再揭示内容，支持查找词汇 | 本轮改为默认收起回看提示，先读原句回忆，再主动展开；搜索只查公开题干字段 |
| [Anki 学习原理](https://docs.ankiweb.net/manual/background) | 主动回忆与间隔重复 | 不把阅读答案当作独立作答；查看提示不产生掌握、分数或正式等级 |

不采用用错一次就扣生命、强制购买、未经验证的能力标签等设计。本平台的核心仍是词、句、段、篇、时代之间的证据联系，不能退化成只记住答案位置的闪卡。

## 已落地的复习改进

入口是 `#/review`，沿用现有 `GET /api/v1/profiles/{id}/mistakes` 数据和原有训练创建接口。

- 默认仅展示原句、回看词和回忆问题，提示文本在用户主动展开后才挂载到页面中，可用键盘操作。
- 按篇目、来源、字词和原句查找当前已加载的错题，不搜索隐藏提示，避免通过搜索提前泄露提示。
- 按最近作答、累计错答次数、较久未作答排列。日期缺失或非法时，时间排序放在末尾；同序时按课程 ID 稳定排序，不修改原始数据。
- 首次展示 10 项，再按 10 项加载，明确告知匹配数量与展示数量。此处是前端分批展示，不是服务端分页。
- 重练仍回到原关卡并遵循原有判题、辅助记录和积分规则；本页面的展开、搜索、排序不写入学习数据库，不调用模型。
- 最近作答日期按北京时间显示，避免把作答事件错误标为复习事件。更换学习档案或底层题目内容后，展开状态不沿用。
- 手机布局为单列，操作目标至少 48 像素高，提供焦点样式与减弱动画支持。

主要实现：`frontend/src/components/ReviewRecallBoard.tsx`、同目录 `reviewRecall.css`、`frontend/src/reviewRecall.ts`。`App.tsx` 只替换错题列表区域，最近训练、继续练习和其他页面保持原有流程。

## 下一批开发顺序

先实现持久化间隔复习，再优化学习路径。不要直接套用未经本平台数据验证的遗忘曲线或声称复现了竞品内部算法。

1. 为具体知识点或语境义项建立复习项，而不是只给整篇课文一个到期时间。记录档案、内容版本、首次独立作答、辅助使用、最近练习、下次建议时间和调度版本。
2. 以服务端真实完成事件和已有辅助轨迹更新调度。增加幂等事件键，防止双击、刷新、重复回包推进多次；历史数据没有证据时保留未知，不补造成功记录。
3. 首版采用明确标为规则版的可配置时间间隔。先做离线回放与时间边界测试，再考虑经许可评估的 FSRS 实现；不混用自报熟悉与独立答对。
4. 提供今日到期、薄弱项与新内容三个入口，解释推荐原因，并保留按篇目自主练习。无可用审核内容时显示缺口，不生成假题。
5. 再把同字不同义、同义不同篇的迁移练习穿插进路径。解锁基于真实前置任务；不以积分或看过提示替代正式能力审核。

数据库迁移、后端事件与调度测试、复习队列前端应按接口契约分工。接续开发前确认 Harness 对话的文件所有权，尤其不要并行覆盖 `backend/main.py`、模型配置与协作桥模块。
